What’s new? Greenspector release note v.2.9.0

June 11, 2021Technical Zone

The Greenspector team is proud to announce its latest release v.2.9.0.

To measure application and website consumption, you can run user journeys on our smartphone farms. In this context, we have improved our simplified test language (GDSL) with, for example, features for preparing browsers but also taking Firefox into account… Unlike many tools that provide you with an environmental impact only on the main page and on simulated environments, these capabilities will allow you to assess and monitor the impact of your digital solution!

NEW FEATURES

– As an automation engineer, I can now use the GDSL browser methods with Firefox (Android only)
– As an automation engineer, I can use some new GDSL methods for iOS testing (waituntiltextgone, swipe) (iOS only)
– As an automation engineer, I want new GDSL browser methods which prepare the browser for the measurement so that I can focus myself on websites measurement (Android only)

IMPROVEMENTS

– Improve the GDSL resetBrowser method by configuring chrome to reduce regular data exchanged (Android only)
– Add new unit tests for all GDSL methods interacting with Chrome so that it is easier to expand support for different phones and chrome versions (Android only)
– Increase GDSL default timeout for wait methods and handle errors for find methods (iOS only)
– Add API swagger for existing routes applications (GET, DELETE application), audits (GET), and testbench (POST job, GET job)
– During the execution of a test in iOS device, remove software probe, only use hardware probe to get platform discharge

FIXED BUGS

– Fixes and secures GDSL methods interacting with Chrome by adding assertions to guarantee the actions
– Fixes empty points when measuring energy by the hardware probe which prevented the sending of test results

IDENTIFIED BUGS

– « Undefined » value that was displayed on the process data metrics on the meter tab of the web interface
